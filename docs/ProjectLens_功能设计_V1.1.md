## 1. 文档目的与范围

### 1.1 目的

- 将《`ProjectLens_需求与设计文档_V1.0.md`》中的“功能需求详述”落到可实施粒度：**页面**、**用户流程**、**关键交互**、**状态与权限**、**主要验收点**。
- 明确模块边界，避免后续详细设计/实现阶段跨模块复制逻辑。

### 1.2 范围

- 覆盖核心业务模块：**（当前实现）项目选择与注册、设置（规则/预设/模型/分块策略）、一键执行全流程（转换→索引→流式审查）、会话与追问、结果导出与下载索引**。
- 规划模块（非当前实现）：项目仪表盘、文档浏览器三栏、标注体系、知识库、任务队列、跨项目检索等。
- 不包含：模型/向量库/队列等技术选型比较（见技术架构文档）、算法细节（在详细设计中展开）。

### 1.4 当前实现范围（以代码为准）

当前 Web 产品的“最短闭环”以首页为主：

- **初始化与分析分离**：先在「项目初始化」完成 docs2md 转换 → 索引与分块；再在「分析」视图进行流式审查与多轮追问。
- **自动编排（模式 C）**：分析页不要求用户选择预设；系统根据用户输入自动路由关注点组合并决定本轮执行（审查/追问/澄清/提示初始化）。
- **证据追溯**：输出包含片段编号；流程中/结束后生成“片段与来源索引”，并可导出为独立文件。
- **会话与追问**：按项目保存会话（conversation），支持在已有分析基础上追问（SSE）；输出文件（最终 md/里程碑/片段索引等）可在“输出索引”中下载。
- **导出**：支持导出 Markdown；docx 由后端调用 `epic-doc` 生成（本项目不实现排版引擎）。

### 1.3 约定

- **统一接口调用**：LLM、文档解析、向量检索、报告导出均通过统一 Provider/Adapter 接口调用；本功能设计只描述接口“契约”，不重复实现逻辑。
- **统一返回结构**（后端 API）：

```json
{
  "status": "success|error",
  "data": {},
  "message": "optional"
}
```

## 2. 角色、权限与数据隔离

### 2.1 角色模型（产品层）

| 角色 | 典型用户 | 核心权限 | 关键限制 |
| :-- | :-- | :-- | :-- |
| 实施顾问 | 交付顾问 | 创建/配置项目；文档导入；发起分析；标注编辑；生成报告 | 不可管理全局模型密钥（可选） |
| 项目经理 | PM | 发起评审；查看仪表盘；发布报告；设置里程碑 | 不能修改他人标注（可配置） |
| 质量评审专家 | QA/审计 | 查看证据链；生成/编辑评审报告；冻结版本 | 不可改项目基础配置（默认） |
| 售前顾问/销售 | Presales | 跨项目知识检索；导出行业洞察 | 默认只读，不可访问敏感原文（脱敏） |
| 知识管理员 | KM | 维护知识条目；模板管理；敏感词/脱敏规则 | 不参与项目交付流程 |
| 系统管理员 | Admin | 用户/权限；模型密钥；存储与审计 | 访问受审计记录约束 |

### 2.2 数据隔离（产品要求）

- **项目隔离**：不同项目的原文与标注默认不可跨项目访问，除非被“提炼为知识条目”并脱敏。
- **原文最小暴露**：对售前/知识库用户，默认只展示摘要/引用片段；原文访问需显式授权。
- **审计要求**：所有“导出/分享/跨项目引用”行为必须落审计日志（不记录敏感原文全文）。

## 4. 模块一：项目与文档管理（Project & Document）

### 4.1 页面：项目列表（Project List）

#### 4.1.1 主要能力

- 新建项目（选择项目根目录 / 云存储路径）
- 项目卡片：行业、规模、文档数、最后同步时间、健康度（如已生成）
- 过滤/排序：行业、健康度区间、创建时间、最近更新

#### 4.1.2 关键交互

- **新建项目向导**
  - 步骤1：填写项目名、行业、规模、标签
  - 步骤2：选择项目根目录（本地/对象存储）
  - 步骤3：目录扫描预览（阶段识别、文件类型统计）
  - 步骤4：创建并开始索引

#### 4.1.3 验收点

- 选定目录后 2 秒内返回“预览统计”（允许后台继续扫描，但必须先给出可视反馈）。
- 同一目录重复创建项目需提示并引导“关联已有项目”或“新建快照”。

### 4.2 页面：项目详情 / 仪表盘（Project Dashboard）

#### 4.2.1 信息区块

- 概览：行业、规模、标签、阶段覆盖、最近活动
- 文档统计：总数、按阶段/格式分布
- 分析统计：最近分析任务、成功/失败、耗时、Token 消耗（若启用）
- 风险概览：高/中/低风险数量、待确认事项数量
- 待办：待确认标注、待导出报告、失败任务重试

#### 4.2.2 验收点

- 任何统计卡片点击后能跳转到“可解释明细列表”（不是只有数字）。

### 4.3 页面：文档浏览器（Document Explorer）

#### 4.3.1 三栏布局（建议）

- 左：文件树（阶段分组 + 搜索 + 筛选）
- 中：文档内容预览（Markdown/转换结果；支持目录大纲）
- 右：标注面板（按类型过滤、跳转原文、编辑/验证）

#### 4.3.2 文档状态

| 状态 | 含义 | 触发 |
| :-- | :-- | :-- |
| `indexed` | 已建索引（元数据/结构） | 完成扫描与解析 |
| `chunked` | 已分块 | 完成 chunk 切分 |
| `embedded` | 已向量化 | embedding 完成 |
| `analyzed` | 已提取 | 至少一次提取任务成功 |
| `error` | 处理失败 | 解析/分块/向量化/提取失败 |

#### 4.3.3 关键交互

- 文档内搜索：关键词高亮
- “查看原文”与“查看结构化版本”（例如 `.docx` 转 Markdown）
- 文档级操作：重新解析、重新分块、重新向量化（管理员/顾问权限）

#### 4.3.4 验收点

- 每一条标注必须有“证据跳转”（来源文档 + 段落定位）；无法定位时必须标记“证据不可用”并给原因。

### 4.4 功能：项目快照（Snapshot）

- 创建快照：记录某时间点文件清单与摘要信息，用于比对
- 快照对比：新增/删除/修改文件列表；重要指标变化（文档数、标注数、风险数）

验收点：
- 快照创建不应阻塞用户浏览；可后台完成，完成后提示。

## 5. 模块二：智能内容提取与标注（Extraction & Annotation）

### 5.1 页面：分析工作台（Analysis Studio）

#### 5.1.1 主要能力

- 选择范围：项目/阶段/文档集合
- 选择任务类型：摘要、需求提取、风险识别、决策点提取、依赖关系提取、实体识别
- 选择模型：默认 / 任务级覆盖
- 发起任务：同步串行执行为主（转换/索引/审查），前端以 **SSE** 实时展示日志与流式输出
- 结果浏览：按类型、置信度、来源、阶段聚合

#### 5.1.2 任务状态机

| 状态 | 含义 |
| :-- | :-- |
| `queued` | 已入队等待执行 |
| `running` | 分析执行中（可能分文档/分 chunk 流式） |
| `partial_success` | 部分文档成功，部分失败（可重试失败部分） |
| `succeeded` | 全部成功 |
| `failed` | 失败（含原因码与可重试提示） |
| `cancelled` | 用户取消 |

#### 5.1.3 验收点

- 进度必须可解释：展示“当前正在处理的文档/阶段/步骤”（解析/分块/embedding/LLM）。
- `partial_success` 必须提供“一键重试失败项”。

### 5.2 标注体系（产品层）

#### 5.2.1 标注字段（最小集合）

- 类型：需求/风险/决策/依赖/知识点
- 状态：confirmed/pending/out_of_scope（仅对需求类）
- 置信度：high/medium/needs_review
- 来源：ai_generated/human
- 证据：doc_id + chunk_id + 原文片段 + 偏移（可选）
- 归属：模块/阶段/标签（多值）
- 审阅：is_verified + verified_by + verified_at

#### 5.2.2 标注工作流

- AI 生成 → 人工审阅 →（确认/驳回/编辑/补证据）→ 可导出到报告

验收点：
- 人工编辑后必须保留“历史版本”或“变更轨迹”（最小：modified_at + modified_by + diff 摘要）。

### 5.3 页面：标注面板（Annotation Panel）

#### 5.3.1 主要能力

- 列表：按类型分组 + 颜色标识 + 过滤
- 详情：内容、证据、置信度、标签、评论
- 操作：确认/驳回、编辑、补充评论、标记已验证
- 关联：把标注拖入报告章节（或“添加到报告草稿”按钮）

#### 5.3.2 验收点

- 标注导入报告后应形成“引用块”，保留证据链接（报告中也要可追溯）。

## 6. 模块三：方案助理（Solution Assistant）

### 6.1 能力一：行业洞察检索（Knowledge Search）

#### 6.1.1 输入与输出

- 输入：行业（可选）、关键词 query、筛选（模块、风险等级、时间范围）
- 输出：
  - 高频需求 TopN
  - 高频风险 TopN
  - 典型交付物清单
  - 可复用片段（脱敏）

#### 6.1.2 验收点

- 对每条洞察必须显示“来源项目数/样本量”，避免“凭空生成”。

### 6.2 能力二：需求审查（Requirement Review）

#### 6.2.1 分析维度（产品功能输出）

- 需求完整性：对标行业典型需求集，输出“可能遗漏”清单（带建议追问）
- 需求-方案一致性：调研 ↔ 蓝图映射断层列表
- 需求-任务追溯：蓝图 ↔ 任务映射缺口与覆盖率
- 范围蔓延：蓝图完成后新增需求识别与影响提示

#### 6.2.2 页面呈现（建议）

- 左：需求清单（来自调研/蓝图/任务三类）
- 中：映射关系图/表（需求 → 蓝图章节 → 任务）
- 右：问题与建议（按严重程度排序）

验收点：
- 任何“断层”必须可点开看到“证据链”（相关文档片段/任务字段）。

## 7. 模块四：项目评审助理（Review Assistant）

### 7.1 页面：评审发起（Create Review）

#### 7.1.1 输入项

- 评审范围：阶段范围（调研→蓝图 / 蓝图→开发 / 全项目）
- 报告模板：内置/自定义
- 模型配置：默认/覆盖
- 输出格式：docx/pdf/md（可多选）
- 评审人：责任人/抄送（可选）

#### 7.1.2 验收点

- 评审范围必须影响“证据选择集”（不能只是报告标题变化）。

### 7.2 页面：报告编辑器（Report Editor）

#### 7.2.1 编辑形态

- 章节树（拖拽排序）
- 章节内容（块编辑）
  - AI 生成块与人工编辑块区分样式
  - 引用块：标注/原文片段
  - 表格块：风险矩阵/检查清单
  - 图表块：覆盖率、时序分布等

#### 7.2.2 报告版本

- 草稿（Draft）
- 冻结（Frozen）：作为评审基线（不可再自动重写；允许另存新版本）
- 已导出（Exported）：记录导出时间与格式

验收点：
- 冻结后必须能“从冻结版本复制创建新版本”，避免直接修改审计基线。

### 7.3 内置模板（产品视角）

#### 7.3.1 模板：全项目分析报告

- 执行摘要：项目基本信息、核心发现、总体评分（可选）
- 调研→方案：需求承接分析（覆盖率、断层、待确认）
- 方案→任务：开发覆盖分析（映射与缺口）
- 时序分析：任务创建时间分布、里程碑缺失
- 检查清单：逐项通过/待确认/不通过（带证据）
- 改进建议：按优先级给行动建议

#### 7.3.2 模板：阶段性轻量评审

- 调研阶段：需求完整性、调研深度、待确认事项
- 蓝图阶段：方案覆盖率、验收标准、权限矩阵完整性
- 上线前：Go/No-Go 门禁清单

## 8. 设置与配置（Settings）

### 8.1 模型配置（LLM Providers）

#### 8.1.1 配置项

- 默认 Provider/Model
- 任务级覆盖（摘要/提取/报告）
- 参数：temperature/max_tokens/timeout
- 代理设置
- 连接测试

#### 8.1.2 安全要求

- API Key 仅管理员可见与管理；普通用户只看到“已配置/未配置”状态。
- 日志禁止打印密钥与原文全文。

### 8.2 模板管理

- 提示词模板：系统级不可改；任务级可克隆；自定义模板可版本化
- 报告模板：章节结构、检查项清单、样式配置

### 8.3 文档分块策略（Web 设置）

- **配置入口**：设置页与 `app_settings.md` 中的 `chunk_strategy` 字段，取值 `blank`（空行分段 + 字数装箱，与升级前一致）或 `structured`（`.md` 按 ATX 标题与代码围栏分节后再装箱；`.txt` 仍走空行管线）。
- **权威来源**：以 Web 保存的设置为准；执行「索引与分块」时后端读取该值并传入索引器。**修改策略后须重新索引**，否则分析仍基于旧 chunk；保存策略变更后系统应提示用户重新索引。
- **审查输出**：模型输入中每个片段块头携带文件路径、章节（结构策略下有标题路径，否则为「—」）、行号范围；流式分析结束后在 Markdown 正文末尾**确定性追加**「片段与来源索引」表（与送入模型的片段序号一致）。

### 8.4 分析流程展示（当前 Web）

- 全流程执行时，在里程碑列表上方展示约 150～200 字的**任务说明**（项目名、关注点摘要、三阶段说明）。
- 里程碑详情：**进行中**默认展开，**完成/失败**默认折叠；用户手动展开/收起后记住该次选择。
- 全流程成功结束时在流程区展示 **「已完成。」**（失败或用户终止不展示）。

### 8.6 会话、追问与输出下载（当前 Web）

- **会话（conversation）**：按项目保存会话列表；创建会话时可带 `preset_id` 便于追溯“用哪个预设完成的审查”。
- **预设历史**：当用户切换预设并准备执行时，系统可查询该预设是否已有“最近一次已审查”的会话，便于复用历史或提示新建。
- **追问（followup）**：基于“上一轮分析结果（摘要/截断）+ 本次 chunks”进行证据驱动追问；若引用证据要求标注片段编号。
- **输出索引与下载**：每次分析/追问生成的导出文件（最终 md、里程碑日志、片段索引等）在输出索引接口中可查询并通过下载接口获取。

### 8.5 审查技能包与组合预设（当前 Web）

- **入口**：设置页 **「审查域」**；顶栏提供当前活动技能包与 `review_domain.md` 路径提示，并支持从本机选择文件进行校验/导入，写回当前活动包。
- **子页签 — 关注点**：左侧为关注点列表，右侧为名称与审查 Prompt 编辑区；数据源为当前活动包的 `review_domain.md`。
- **子页签 — 预设组合**：列表展示由 `review_domain.md` 中「组合使用建议」**五列表**推导的预设（及用户保存后的结果）；每条含名称、包含的关注点（多选），以及三个多行文本：**审查角色**、**审查目标与原则**、**输出要求**（与表格后三列同源，可在此覆盖后保存写回）。
- **活动审查域文件格式**：`## 组合使用建议` 下为固定五列表（列名见用户手册）；推荐列仅允许 `` `focus:关注点id` `` 形式且与 `### focus:…` 的 id 一致；单元格内换行、竖线转义约定见产品帮助（`helpme.md`）。
- **联动（当前实现）**：分析页不展示预设选择；系统会根据用户输入自动路由关注点组合，并按需注入技能包元数据与记忆召回片段。

### 8.7 审查技能包、记忆、工具与钩子（功能视角）

- **审查技能包（Skills）**：用户在 **设置 → 审查域** 切换**活动包**；包内含 `review_domain.md`（关注点与组合表）。切换包后，新一次全流程审查使用新包下的关注点与预设推导结果（与后端 `active_skill_package_id` 一致）。
- **记忆（Memory）**：用户在输入栏可填 **「记忆检索（可选）」** 覆盖默认检索词；未填时由后端用关注点名称拼接检索。记忆文件存放在服务端仓库根 **`.aika/memory/`** 下（见《需求与设计》第十二章）。审查流式结束后，若本轮有注入记忆，在 **「思考分析」** 里程碑正文中追加 **「【加载的记忆】」** 列表（相对路径与标题摘要），便于确认召回来源。
- **工具（Tools）**：面向集成与运维的 **HTTP 工具调用**（`/api/v1/tools/invoke`），普通审查主路径不强制使用；用于校验审查域、占位指标等。
- **钩子（Hooks）**：对用户**无直接配置界面**；服务端在分析前后执行已注册逻辑（默认仅审计日志）。扩展记忆注入需通过服务端 hook 写入 `extra_memory_snippets`（实现级，见详细设计）。

## 9. 关键验收清单（跨模块）

- **证据链**：所有结论可追溯到来源文档/段落/任务字段。
- **可重试**：长任务失败后能定位失败粒度，并支持重试失败部分。
- **可解释进度**：进度不仅是百分比，还要显示步骤与当前对象。
- **冻结基线**：报告与关键标注支持冻结并可审计。
- **权限与脱敏**：跨项目检索与分享必须脱敏并记录审计。

## 10. 与 `epic-doc` 的关系（约束）

- 本项目**不实现** docx 排版/图表/流程图生成逻辑。
- 所有 Word 报告输出由 `epic-doc` 生成（CLI 或库方式），本项目只负责：
  - 组织报告结构与数据（JSON/块列表）
  - 调用 `epic-doc` 生成 `docx`（或由外部流水线调用）
