## 一、功能定位

通过 AI 主导的结构化对话，把专家头脑中的隐性知识——判断规则、风险信号、最佳实践——转化为可验证、可入库的**知识卡片**。

**核心交互循环：**
```
AI 提问（六种策略）→ 专家回答 → AI 实时提炼 → 知识卡片确认 → 同步入库
```

知识卡片一经确认，**同时写入个人知识库与组织知识库**（组织侧进 Pending 队列，管理员审批后全组生效）。

**完整会话记录**自动保存为结构化 Markdown 文件，命名格式：
```
知识提取_<专家姓名>_<方向标签>_<YYYYMMDD>.md
```
例：`知识提取_张伟_上线陪跑_20260512.md`

## 二、登录

进入系统后需先登录。

- 输入用户名和密码
- 账号由管理员在后台创建（后端用户表管理）
- 登录后右上角显示姓名，知识卡片和会话记录均与账号绑定

> 登录的主要作用是**身份识别与专家画像保存**，不用于功能权限门控——任何登录用户均可使用知识提取功能。

## 四、开始会话

点击「+ 新建会话」，AI 根据你的画像确认今天的方向：

```
你好，张工。根据你的背景，你擅长汽车零部件行业的上线陪跑阶段。
今天想从哪里开始？

○ 我来问，你来答（AI 主导提问）
○ 分享一份你觉得做得好的文档
○ 分享一份有问题的文档
○ 直接说你想聊的内容
```

选择后进入主对话界面。

## 五、对话过程

### 5.1 AI 的六种提问策略

AI 根据对话上下文动态选用以下策略，每轮只问 **1 个主问题**。

---

**① 关键事件法**（Critical Incident Technique）

锚定到真实案例——专家的记忆和判断在具体事件中才会被激活。

> 「说一个你印象最深的、上线后陪跑时间特别长的项目，当时到底卡在哪？」

---

**② 对比法**

对比逼出判断标准——专家可能说不清什么是好蓝图，但说得清两个项目的差异。

> 「你做过最顺的项目和最难收尾的项目，蓝图阶段有什么明显的区别？」

---

**③ 规则边界法**

隐性知识往往藏在规则的边界条件里，追问"什么时候不适用"比追问"怎么做"更有价值。

> 「你说蓝图要在 X 周内确认，有没有你主动延长这个时间的情况？是什么让你做了例外决定？」

---

**④ 反事实法**

让专家想象没有做某个决策的后果，揭示他真正在保护什么。

> 「如果当时你没有在蓝图阶段坚持那个决定，你预判会发生什么？」

---

**⑤ 协议分析法**（Think Aloud）

当专家给出模糊的直觉性回答时，逼出具体的观察指标。

> 「你刚才说'靠感觉判断客户是不是真的理解了蓝图'——能不能把这个感觉具体化？你在观察什么？」

---

**⑥ 文档交叉验证法**

文档不只是信息来源，也是触发专家记忆和反思的锚点。

> 「你说这类需求通常能用产品配置实现，能不能找一个你觉得做得好的蓝图文档，我们一起看看你当时是怎么处理类似情况的？」

---

### 5.2 模糊信号自动追问

AI 自动检测回答中的模糊词，下轮直接追问例外，无需手动触发：

| 检测到的词 | 触发追问 |
|---|---|
| 通常、一般、大多数情况 | 「什么情况下会不一样？」 |
| 要看情况、视项目而定 | 「最关键的判断因素是什么？」 |
| 感觉、经验告诉我 | 「这个感觉背后，你在观察什么具体信号？」 |
| 基本上、差不多 | 「有没有你记得的反例？」 |

---

### 5.3 文档随时可上传

对话任意时刻点击输入框旁「📎」上传文档（Word/PDF/Markdown）。

上传后 AI 立即切换策略，基于文档具体内容提问，而非继续抽象追问。

## 六、知识卡片确认（核心交互）

每当 AI 从对话中提炼出一条完整知识，**自动暂停提问**，展示卡片请求确认：

```
─────────────────────────────────────────
📋 知识卡片 #3 · 风险信号

当客户在蓝图确认阶段频繁更换对接人时，
通常意味着内部需求尚未对齐。

建议行动：在蓝图签字前，要求客户组织
一次内部对齐会议，确认决策链已完整。

适用范围：合同型项目 · 蓝图确认阶段
例外情况：对接人变更是计划内的职位调整
置信度：高
─────────────────────────────────────────
这个描述准确吗？有没有需要补充或修正的？

  [✅ 确认入库]   [✏️ 修改后入库]   [❌ 不采纳]
```

- **确认入库**：卡片立即同步写入个人知识库和组织知识库（组织侧进 Pending）
- **修改后入库**：弹出编辑界面，修改任意字段后确认
- **不采纳**：卡片丢弃，不记录

确认后 AI 自动进入下一个话题。

---

## 七、知识卡片字段说明

| 字段 | 说明 | 示例 |
|---|---|---|
| **类型** | 风险信号 / 判断规则 / 操作流程 / 最佳实践 / 反面案例 | 风险信号 |
| **核心内容** | 规则类：IF [条件] THEN [行动]；流程类：步骤列表 | 当…时，意味着…建议… |
| **适用范围** | 行业 / 生产模式 / 项目阶段 | 合同型项目，蓝图确认阶段 |
| **例外情况** | 不适用的场景 | 对接人变更是计划内调整 |
| **置信度** | 高（多次验证）/ 中（个人经验）/ 低（推测）| 高 |

## 十一、验收测试场景

| 编号 | 场景 | 验收标准 |
|---|---|---|
| T01 | 首次登录，用户名密码验证 | 错误密码提示错误，正确密码进入主界面 |
| T02 | 首次进入知识提取，完成专家画像 | 4 个问题依次展示，多选可用，回答后保存 |
| T03 | 再次进入知识提取 | 画像自动加载，AI 开场问候中提及已知背景 |
| T04 | 更新画像（修改擅长行业）| 下次会话使用新画像 |
| T05 | 选「AI 主导提问」，收到第一个问题 | 问题与画像中选择的方向一致，非通用问题 |
| T06 | AI 使用关键事件法提问 | 问题锚定到具体项目/案例，不是抽象问题 |
| T07 | 回答含「通常」，下轮 AI 追问例外 | 自动触发，无需手动操作 |
| T08 | 对话 2-3 轮后，AI 暂停展示知识卡片 | 卡片含 5 个字段，格式正确 |
| T09 | 对卡片点「修改后入库」 | 弹出编辑界面，所有字段可修改，确认后入库 |
| T10 | 对卡片点「不采纳」 | 卡片消失，不写入任何知识库 |
| T11 | 确认一张卡片 | 个人知识库新增文件 + 组织 Pending 队列新增一条 |
| T12 | 对话中途上传文档 | AI 下一个问题基于文档具体内容，策略切换为文档交叉验证法 |
| T13 | 选「分享一份差的文档」 | AI 先用对比法问哪里不好，再用规则边界法追问正确做法 |
| T14 | 说「结束」 | 显示摘要（卡片统计、文件名），文件已保存 |
| T15 | 打开提取历史，重新打开旧会话 | 历史卡片状态正确，可继续新对话 |
| T16 | 检查保存的 Markdown 文件 | 命名规范，包含对话记录和卡片两个区块，结构清晰 |
