# AI-KA 知识提取功能 用户手册 v1.4

**版本**：v1.4  
**日期**：2026-05-13  
**适用版本**：AI-KA v1.x 知识提取模块

---

## 一、功能定位

通过 AI 主导的结构化对话，把专家头脑中的隐性知识——判断规则、风险信号、最佳实践——转化为可验证、可入库的**知识条目（KI）**，并最终经人工审批写入**审查技能包**。

**核心交互循环：**
```
AI 主动提问（四种策略）→ 专家回答 → AI 实时提炼知识条目 → 内联审核（确认/修改/不采纳）→ 批量审批写入技能包
```

每次提取会话的对话记录自动保存为结构化 Markdown 文件。

---

## 二、权限与前置条件

知识提取的完整功能（主动提取、文档上传、待批准规则审批）需要以下环境变量：

```bash
AIKA_USER_ROLE=senior_expert
```

在 Docker 或本地启动时通过 `.env` 或命令行设置。未设置时，页面显示「权限不足」提示。

> **注意**：知识提取模块不依赖独立的用户账号系统，权限通过环境变量控制。

---

## 三、模块入口

左侧导航栏点击**灯泡图标（🔆）**切换到「知识提取」模式，页面顶部两个标签页：

| 标签 | 功能 |
| --- | --- |
| **提取工作台** | 三种开始方式的统一会话界面（审查后提取 / 自由提取 / 文档澄清） |
| **待批准规则** | 审批 LLM 提取的知识条目，批准后写入活动技能包 |

在「项目审查」模式下，左侧导航栏还有**审查队列**图标（🔍），点击后右侧抽屉展开。

---

## 四、专家画像（首次进入）

**首次进入知识提取**时（且专家画像尚未建立），系统启动 AI 引导的三步入职访谈：

1. **Step 1 — 专业领域**：从动态生成的领域列表中多选擅长方向（领域选项根据审查队列内容分布生成，至少选一个才能继续）
2. **Step 2 — 工作背景（可选）**：描述工作年限、典型项目类型、常遇挑战等
3. **Step 3 — 确认**：预览画像摘要，点击「保存并开始提取」完成初始化

画像保存至 `~/.aika/memory/user/expert_profile.md`，重启后自动加载。之后进入知识提取将跳过访谈，直接进入提取工作台。

> 如需修改画像，点击右上角「专家画像」→ 编辑领域并保存；或直接编辑文件后刷新页面。

## 五、提取工作台

### 5.1 三种开始方式

工作台顶部分段选择器切换不同模式：

| 方式 | 适用场景 | 操作 |
| --- | --- | --- |
| **从审查队列** | 针对项目审查后产生的知识线索深入提炼 | 从下拉框选择队列条目 + 选择提取策略 |
| **自由提取** | 主动提炼某个领域经验或规则 | 选择提取策略 + 描述主题 |
| **文档澄清** | 上传已有规则文档做知识澄清 | 拖拽上传 `.md` / `.html` 文件 |

三种方式共用同一对话界面（ChatArea + 知识条目卡片 + 场边教练提示）。

### 5.2 四种提取策略

| 策略 | 适用场景 | LLM 行为 |
| --- | --- | --- |
| **规则差距（gap_based）** | 想系统梳理现有规则空白 | 对比审查队列与当前规则库，识别未覆盖模式 |
| **模糊信号（fuzzy_signal）** | 有模糊感觉但说不清楚 | 追问细节，帮你把印象转化为清晰规则 |
| **关键事件（critical_incident）** | 有具体案例或事故想提炼规律 | 基于事件细节追问，提炼可复用经验规则 |
| **反向验证（reverse_validation）** | 想确认/修正一条已有规则 | 提出质疑场景，专家确认或反驳，迭代规则边界 |

### 5.3 对话流程

1. LLM 根据所选策略主动提问（每轮只问 1 个主问题）。
2. 你在输入框作答；AI 会自动检测模糊词（「通常」「要看情况」等）并下轮追问例外。
3. ChatArea 下方**满意度进度条**实时显示 LLM 对已提取知识的置信程度（0–1）：
   - **橙色（< 85%）**：建议继续追问
   - **绿色（≥ 85%）**：满意度达标，LLM 自动生成知识条目
4. 满意度达标（或最多 5 轮）后，知识条目以内联卡片形式出现在对话流中，请求确认。

## 六、内联知识条目审核

LLM 每次生成知识条目，以卡片直接嵌入对话流中：

```
─────────────────────────────────────────
📋 知识条目 · 风险信号

当客户在蓝图确认阶段频繁更换对接人时，
通常意味着内部需求尚未对齐。

适用范围：合同型项目 · 蓝图确认阶段
例外情况：对接人变更是计划内的职位调整
置信度：高
─────────────────────────────────────────
  [✅ 确认入库]   [✏️ 修改后入库]   [❌ 不采纳]
```

| 操作 | 说明 |
| --- | --- |
| **确认入库** | 采纳该条目，标记为 `approved`，发送到「待批准规则」列表 |
| **修改后入库** | 弹出编辑弹窗，修改标题/内容/适用范围后确认，状态为 `edited` |
| **不采纳** | 拒绝该条目，不进入规则库 |

## 七、场边教练（Coach Agent）

每隔 **5 轮对话**自动触发，对话区底部出现绿色教练提示条：

| 字段 | 说明 |
| --- | --- |
| 核心建议（whisper） | 1–2 句，建议的下一轮提问方向 |
| 专家类型推断 | 如「偏执行派，不善理论化」 |
| 未覆盖领域 | 识别到的知识空白列表 |
| 对话势头 | 「停滞」/「减弱」时显示警告标签 |
| 风险标记（flag） | 如「警惕：专家开始给教科书式答案」 |

- 点击「**采纳建议**」：whisper 内容预填到输入框，可直接发送或修改
- 点击「**忽略**」：关闭提示，继续自主对话
- 教练提示**仅对操作员可见**，不注入 AI 上下文

## 八、待批准规则

所有由 LLM 提取、等待人工确认的知识条目集中在「**待批准规则**」标签页。

**操作**

| 操作 | 说明 |
| --- | --- |
| **批准** | 将规则写入活动技能包（新关注点或现有关注点版本升级） |
| **拒绝** | 填写拒绝原因后标记 `rejected`，不写入规则库 |
| **展开行** | 查看完整内容与适用范围 |

批准后规则写入 `review_skill_packages/<包id>/focus-points/` 目录；可在 **设置 → 审查域** 中验证。

---

## 九、审查队列（Review Queue）

项目审查与知识提取之间的缓冲层，暂存来自审查结论的泛化知识线索。

**入口**：在「项目审查」模式下点击左侧**审查队列图标（🔍）**，右侧抽屉展开。

**线索来源**：每次项目审查结束后，LLM 自动识别结论中可泛化知识点并写入队列；每条线索包含关联关注点 ID、建议摘要、来源（项目/会话 id）、重复次数。

**查看与使用**
- 列表按重复次数降序排列（同一建议多次出现时合并计数）
- 可在抽屉中直接变更状态或删除条目
- 在「从审查队列」模式下发起提取时，系统自动携带所选条目
- 「规则差距」策略优先覆盖高优先级队列项

## 十、审查后提取（Post-Review Extraction）

在项目审查结果页点击「**提取知识**」，自动切换到知识提取模式：

1. LLM 解析本次审查结论，识别可泛化知识点
2. 点击「开始提取」发起第一轮对话
3. 支持多轮追问、内联 KI 卡片审核、场边教练提示

## 十一、自学习飞轮

| 层级 | 时间尺度 | 实现 |
| --- | --- | --- |
| Scale-1 | 会话内 | 专家建模协议（Expert Modeling Protocol）注入系统提示 |
| Scale-2A | 每 5 轮 | 场边教练 Agent 分析对话历史给出建议 |
| Scale-2B | 会话后 | 元反思（Meta-Reflection）复盘，更新策略有效性分数 |

策略库内置 12 条 Bootstrap 种子策略；首次部署时调用 `POST /api/v1/extraction/strategies/bootstrap` 初始化（幂等）。

## 十二、常见问题

**Q：进入知识提取显示「权限不足」**  
设置 `AIKA_USER_ROLE=senior_expert` 后重启后端服务。

**Q：首次进入没有看到访谈流程**  
如果专家画像已存在（`~/.aika/memory/user/expert_profile.md` 非空），系统跳过访谈。清空画像（右上角「专家画像」→ 清空领域并保存）即可重新触发。

**Q：审查队列没有内容**  
先完成至少一次项目审查。若队列仍为空，检查后端日志中是否有提取错误。

**Q：满意度进度条显示 0% 但已回答多轮**  
满意度由 LLM 内部评估，取决于规则表述是否清晰、适用范围是否界定、是否发现反例。尝试更具体地描述场景并举出例外情况，满意度会上升。

**Q：场边教练不出现**  
教练每 5 轮触发一次。如 5 轮后仍未出现，检查后端日志中 `coach` 相关错误；教练分析失败会静默跳过，不影响主流程。

**Q：批准规则后在审查域中找不到**  
规则写入当前活动技能包的 `focus-points/` 目录。在 **设置 → 审查域** 刷新页面，或检查 `review_skill_packages/<包id>/focus-points/` 目录。

**Q：文档澄清只支持哪些格式？**  
仅支持 `.md` 和 `.html` 格式。Word/PDF 等格式需先转换为 Markdown。
